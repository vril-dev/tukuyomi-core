# はじめに

本書は、**tukuyomi core** を自分の手で導入し、運用していくための日本語ガイドです。

tukuyomi core は、WAF（Web Application Firewall）を組み込んだ HTTP/HTTPS のリバースプロキシです。
受信したリクエストを Coraza または ModSecurity v3 で検査し、アップストリームへ転送します。
検査には、OWASP Core Rule Set（CRS）などのルールセットを使います。

本書では、リリースの入手と最初の起動から始めて、ルールセットの管理、管理画面、ログ、証明書、日々の運用までを説明します。最初から順に読み通せる形にしています。

## 本書の範囲

本書で扱うのは、tukuyomi core 0.2.2 で実装している機能だけです。
実装していない機能や決まっていないことは、そうと分かるように書き、第1章の「1.7　実装しているものと、していないもの」にまとめています。

リポジトリの README が注記しているとおり、製品全体のセキュリティ評価はまだ行っていません。

## 本書の対象読者

本書は、Web サービスの前段に、WAF を組み込んだリバースプロキシを導入し、運用する立場のエンジニア（インフラ、SRE、プラットフォームの担当）を対象にしています。
Linux、HTTP/HTTPS、TLS、systemd の基本的な概念は既知のものとして話を進めます。

## 本書の前提となる tukuyomi core のバージョン

本書は **tukuyomi core 0.2.2** を起点に書いています。
手順に出てくるリリースのファイル名も `v0.2.2` のものです。

以後のリリースで設定キー、コマンド、ログの文などが変わった場合は、本書よりも次のものを優先して確認してください。

- リポジトリのドキュメント
- GitHub のリリースに置かれている、各バージョンのリリースノート

## 本書の読み方

最初から順に読み進めると、入手と最初の起動から本番向けの配置、日々の運用までをひととおりたどれます。

- **第1章** では、tukuyomi core が何をする製品か、どのプロセスで構成されているかを説明します。
  0.2.2 で実装していることと、していないことも整理します。
- **第2章** では、リリースの tarball を使って手で起動し、SQL インジェクションのリクエストがブロックされることを確認するまでを順に示します。
- **第3章** では、systemd を使った本番向けの配置を説明します。
- **第4章から第9章** では、ルールセットと世代、managed 設定と管理画面、アクセス制御とレート制限、ログとログ送信、ACME による証明書、日々の運用をトピックごとに説明します。
  すでに tukuyomi core を動かしている方は、目次から必要な章へ直接進んでかまいません。
- 巻末の **付録A 運用リファレンス** と **付録B 管理リファレンス** には、リポジトリのドキュメント（運用リファレンスと管理リファレンス）の本文を収めています。
  本書の形に替えたのは、見出しの段と、文書の間のリンクだけです。
- **付録C リリースノート** には、0.2.2、0.2.1、0.2.0、0.1.0 のリリースノートを収めています。

各章は、概要、仕組み、設定例、運用上の注意の流れにそろえ、章の頭にその章で分かることを書いています。
どの章も、その章だけで読み切れます。

本文は道案内として、なぜその手順を踏むのか、何から始めるのか、どこで迷いやすいのかを説明します。
設定キーの一覧、値の範囲、細かい注意事項は、付録に任せます。
具体的な設定キーや振る舞いを確認したいときは、本文が案内する付録の節を開いてください。
本文で「付録A 運用リファレンスの「…」」と書いているところは、付録A にある同じ見出しの節を指します。

## 表記について

- 「です・ます」調で統一しています。
- 設定キー、コマンド、ログの文は、ドキュメントと同じ綴りのまま、`proxy.max_body` や `rules import`、`start: listening` のように `code` の書式で書きます。
  ログの文は英語のままです。
- 管理画面の語も、ドキュメントと同じ綴りのまま書きます。
- 技術用語はドキュメントと同じ語を使い、分野で一般に使われるカタカナ語（リクエスト、ログ、ブロック、アップストリーム、ルート、リスナーなど）はそのまま使います。
- 製品名は、本文では tukuyomi core と書きます。
  実行ファイルの名前（`tukuyomi-proxy` など）、ディレクトリ名、ファイル名は、`tukuyomi-core` を含むものも綴りのまま書きます。
  tukuyomi core の元になった製品は、「上流の tukuyomi」と書きます。
- tukuyomi core は root では動かないため、コマンドはサービスの OS ユーザー `tukuyomi` で実行する形（`sudo -u tukuyomi ...`）で書きます。
  コマンドは次のようなコードブロックで示します。

  ```bash
  sudo -u tukuyomi /opt/tukuyomi-core/bin/tukuyomi-proxy config check /etc/tukuyomi-core/config.json
  ```

- `<` と `>` で囲んだ語は、実際の値に置き換える部分の名前です。たとえば、次のものがあります。
  - `<config>`: 設定ファイルのパス
  - `<fingerprint>`: ルールの世代のフィンガープリント
  - `<version>`: managed 設定のバージョン
  - `<engine>`: 検査エンジンの名前（`coraza` か `modsecurity`）
- パスと名前はドキュメントの例に合わせています。設定に書くパスはどれも絶対パスです。
  次のものはどれも例なので、環境に合わせて替えてください。
  - 実行ファイル: `/opt/tukuyomi-core/bin/`
  - 設定ファイル: `/etc/tukuyomi-core/config.json`
  - 状態を置くディレクトリ: `/var/lib/tukuyomi-core` の下
  - OS ユーザー: `tukuyomi`
  - ホスト名: `example.com`
  - ネットワーク: `192.0.2.0/24`

## ドキュメントとの関係

ドキュメントは、tukuyomi core のリポジトリの `docs/` にあります。ファイルの名前は、英語が `foo.md`、日本語が `foo.ja.md` です。
設定キー、コマンド、シグナル、ログの形式、管理 API の定義と振る舞いについては、このドキュメントの記述が正式なものです。
ドキュメントは、システム概要、アーキテクチャ概要、設計方針・制約、ビルドと配置、運用リファレンス、管理リファレンスの文書からなります（`docs/README.ja.md` の「文書の一覧」）。
このうち、システム概要、アーキテクチャ概要、設計方針・制約の文書は初期草案で、目標、前提、候補、未決事項を記録しています（第1章 1.7）。

本書は、ドキュメントを順に読み通せるように組み直した道案内で、ドキュメントにない事実は書きません。
付録A と付録B には、運用リファレンスと管理リファレンスの本文を収めています。
本文からドキュメントのほかの文書を参照するときは、「ビルドと配置」の「ソースからのビルド」のように、文書の名前と見出しで示します。

本書とドキュメントの内容が食い違うように見えるときは、ドキュメントを優先してください。
リリースが新しくなったときも、本書より先に、そのリリースのドキュメントとリリースノートを確認してください。

それでは本編へ進みます。
最初の第1章では、tukuyomi core が何をする製品で、どのようなプロセスで構成されているのかを概観します。
